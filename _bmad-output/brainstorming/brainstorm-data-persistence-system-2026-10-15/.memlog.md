- (technique) started Job to Be Done
- (decision by user) Primary job is J1 durability: save any serializable type, get it back intact
- (insight by user) Versioning = data-FORMAT version: a datatype's JSON shape evolves over time (fields added/removed), so persist a version code alongside the saved data so the loader knows which shape it is reading
- (decision by user) Versioning via KEY SUFFIX (reference pattern): format version is part of the storage key; bumping it makes the loader look under a new key, so pre-bump data is abandoned and load falls back to default. No migration (non-goal).
- (decision by coach) Job statement: durably save/load ANY serializable type, Result<T>-wrapped, backend-swappable, with key-suffix versioning and no cross-version migration
- (technique) started Morphological Analysis
- (decision by user) API shape = Shape A (per-type system): a dedicated IDataSaveSystem per data type, registered in DI. Wants it coupled with dependency injection.
- (note) DI container is VContainer 1.19.0 (Packages/manifest). No LifetimeScope exists in project yet — persistence will be among the first DI-registered systems.
- (decision by user) Axis 2 = A2: shared load/save/version/Result logic lives in an abstract generic base DataSaveSystem<TData>; a concrete per-type subclass supplies only key, format version, default factory, optional validation
- (decision by user) Axis 3 deferred 'for now': no separate injected IStorageBackend seam yet; storage handled within the class hierarchy. Backend abstraction is a future extension.
- (decision by user) Shape 2: abstract DataSaveSystem<TData> holds version/serialize/Result logic and leaves protected abstract ReadRaw(key)/WriteRaw(key,json); backend subclasses (PlayerPrefs, InMemory) fill those holes; per-type concrete picks its backend base. Inheritance seam, not injected — mock is ~2 lines and shares the production serialize/version path.
- (decision by user) Axis 4 serialization = Newtonsoft (com.unity.nuget.newtonsoft-json). Chosen to make 'any serializable type' actually true — dictionaries, nested generics, polymorphism, properties, null. Abstract base uses JsonConvert serialize/deserialize.
- (decision by user) Axis 5 Result model = R1 exception-carrying (mirror reference IResult<T>/Result.Ok/Result.Fail<T>(ex)). Create a new Result<T> in this project. Load/Save return UniTask<IResult<T>>.
- (decision by user) Axis 6 statefulness = S1 stateless save-system: LoadAsync always re-reads/deserializes, SaveAsync writes what it's handed, system owns nothing between calls. Any in-memory 'live instance' / caching / save-cadence service is a separate future concern, out of scope for this system.
- (decision by user) Per-type contract = generic interface IDataSaveSystem<TData> (not named-per-type). VContainer registers closed generics: Register<IDataSaveSystem<PlayerData>, PlayerDataSaveSystem>(Singleton). Named interface only for a type needing bespoke methods.
- (technique) started Failure Analysis (folding/skipping Assumption Reversal — user is firmly reference-aligned and convergent)
- (decision by user) F1 accepted as mandatory: Newtonsoft on IL2CPP/AOT (Mobile build) must be preserved via link.xml (+ [Preserve]/converters) covering Newtonsoft.Json and all persisted data types, or on-device (de)serialize throws. Treated as a required build step, not optional.
- (decision by user) F2 posture = (a) default-and-overwrite (recommended default): base returns Result.Fail(ex) on corrupt/failed read; caller falls back to CreateDefault(); progress may be lost on corruption. Backup-copy (c) deferred as easy future upgrade via the existing ReadRaw/WriteRaw seam.
- (decision by user) F3 = accepted known risk: post-launch format-version bump wipes released players' saves and leaves orphaned PlayerPrefs keys. Acceptable pre-launch; no migration by design.
- (decision by user) Pilot concrete type = PlayerUpgradesSaveSystem (not PlayerData). Persists upgrade state bought during progression: LaunchPower, Speed, SteeringResponsiveness, CollectibleValue (a multiplier applied to collectibles gathered). Default value for every param = 1. Deliverable now: full hierarchy implementation + PlayerUpgrades concrete + a gameplay-scene LifetimeScope binding it.
- (insight) Synthesis: the whole design is one idea — a single ReadRaw/WriteRaw seam — wearing many hats. Every 'flexible/extendable' property is latent in that one hole: new data type = subclass, backend swap = new base over the same hole, test mock = 2 lines, and the deferred trio (injected IStorageBackend, backup-copy corrupt-recovery F2(c), file/cloud backend) ALL hang off that same seam, so none needs a redesign later. R1+key-versioning+S1 keep the base pure persistence; lifetime/caching/migration are deliberately someone else's job. Build order landed: Result<T> -> IDataSaveSystem<T> -> DataSaveSystem<T> -> PlayerPrefs/InMemory bases -> PlayerUpgrades pilot -> VContainer GameplayLifetimeScope.
