- (capability) CAP-1 Publish typed event: system raises event by enum key with typed payload; all current subscribers get it in subscription order, a throwing handler doesn't block others.
- (capability) CAP-2 Subscribe/unsubscribe: consumer registers Action<TEvent> on a key and can remove it; fires until unsubscribed; duplicate subscribe is idempotent.
- (capability) CAP-3 Per-key payload-type safety: each enum key binds one payload type on first use; mismatched payload throws InvalidOperationException, not silent no-op.
- (capability) CAP-4 DI-scoped bus lifetime: concrete buses resolved as VContainer singletons so producers/consumers in a scope share one instance.
- (capability) CAP-5 CoinCollected event: readonly struct carrying Amount, publishable on GameplayEventBus; subscriber receives Amount on collection.
- (decision) Event catalog lives in companion gameplay-events.md (per-entity matrix), not inline kernel; grows as events are added.
- (constraint) Buses are enum-keyed; exactly one payload type per key, enforced at runtime (throw on mismatch).
- (constraint) Payloads are immutable readonly structs implementing marker interface IEvent; no class payloads.
- (constraint) Handler exceptions are caught and logged via Debug.LogException, never propagated out of Publish.
- (constraint) Dispatch snapshots handlers into a pooled buffer so subscribe/unsubscribe during a publish is safe and allocation-free on the steady state.
- (constraint) Buses are DI-provided singletons via VContainer 1.19 within a LifetimeScope; not static/globally accessible.
- (constraint) Project conventions: no comments in code, no coroutines (UniTask only), underscore-prefixed private fields, var, code under Assets/MiraculousSurfers/; Unity 6000.6 URP.
- (constraint) Subscribers own their lifecycle: must Unsubscribe; no weak references, no auto-cleanup of handlers.
- (decision) Non-goal: no static/global singleton event access; buses only via DI.
- (decision) Non-goal: no async/awaitable handlers; no ordering guarantee beyond subscription order.
- (decision) Non-goal: no event buffering/replay/persistence; publish with zero subscribers is dropped; no cross-scene retention.
- (decision) Non-goal: no editor-wired UnityEvents; code-only. No handler priorities, filtering, or once-only subscriptions.
- (decision) Non-goal: not a replacement for direct calls where coupling is acceptable.
- (question) Single GameplayEventBus for all gameplay events, or split by concern as reference did (GameplayEventBus + GameScoreEventBus)? Currently single.
- (question) Does CoinCollected need more than Amount (e.g. world Position for VFX/SFX, or a source id)? Currently Amount only.
- (question) Should a bus auto-Clear() on scope disposal, or is manual Clear the contract? Currently manual; subscribers must unsubscribe.
- (assumption) Assumed one GameplayEventBus suffices for now (single enum GameplayEventType with CoinCollected); split deferred until event count warrants it.
