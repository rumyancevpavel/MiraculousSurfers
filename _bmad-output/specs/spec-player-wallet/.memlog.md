- (note) Distilled from the Player Wallet architecture spine (architecture-player-wallet-2026-10-15). Adopts that spine, ../spec-save-system/SPEC.md, and ../spec-player-upgrades/SPEC.md as companions. Realizes player-upgrades AD-6 and tightens AD-7.
- (capability) CAP-1 Durable balance: coins persist across app restarts. success: add or spend coins, restart, the balance is restored.
- (capability) CAP-2 Gated spend: TrySpend atomically checks and charges. success: TrySpend(price) with Coins>=price returns true and decrements by price (persisted); with Coins<price returns false and changes nothing.
- (capability) CAP-3 Add coins: AddCoins credits the balance and persists it. success: AddCoins(n) raises Coins by n, persists, and fires Changed.
- (capability) CAP-4 Sync read + change notification: Coins is readable synchronously; Changed fires after any balance change. success: a subscriber receives Changed after a spend or add, and Coins reflects the new value.
- (capability) CAP-5 Starting grant: a new player starts with a granted balance. success: first-run load (no saved data) yields the default grant.
- (capability) CAP-6 Consistent purchase (B2): an upgrade purchase never leaves coins durably spent without the upgrade persisted. success: with a forced upgrade-save failure, the coins are refunded and the index reverts, and TryUpgrade reports Applied=false.
- (constraint) Durable stateful service (AD-1): WalletService (IWalletService + IAsyncStartable) is the single owner of live PlayerWalletData; loads on StartAsync (fallback CreateDefault), persists every mutation via IDataSaveSystem<PlayerWalletData>; replaces MockWalletService.
- (constraint) Async A2 contract (AD-2, supersedes player-upgrades AD-6): IWalletService { int Coins {get;} sync; UniTask<bool> TrySpend(int); UniTask AddCoins(int); event Action Changed }. Mutations persist before being treated as committed; negative amounts rejected.
- (constraint) Data & save (AD-3): PlayerWalletData { int Coins }; PlayerWalletSaveSystem : PlayerPrefsDataSaveSystem<PlayerWalletData> (key miraculoussurfers.player_wallet, v1), CreateDefault = starting grant (const, default 1000, tunable), IsValid Coins>=0. Added via save-system CAP-5, no core change.
