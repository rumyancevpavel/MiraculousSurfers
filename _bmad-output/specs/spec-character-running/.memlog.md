- (note) Derived from brainstorm memlog _bmad-output/brainstorming/brainstorm-running-state-movement-2026-10-15/.memlog.md (Creative Partner session, complete). Integrates with spec-gameplay-state-machine.
- (capability) CAP-1 Auto-run forward: after Launch(power, direction) the character continuously runs forward under its own kinematic drive with no per-frame input; initial speed/duration seeded by charge strength, initial heading by aim direction. Success: on Launch the character advances along the aim heading and keeps moving with zero steering input until momentum ends.
- (capability) CAP-2 Lateral steering: the player controls only left/right; steering sets a target lateral offset the character eases toward each frame (target-X lerp). Success: left/right input moves the character sideways smoothly toward the input offset; releasing stops lateral drift; forward motion is unaffected by steering.
- (capability) CAP-3 Stay within bounds: the character cannot leave the playable lateral extent defined by the level's left/right boundary transforms. Success: driving hard into an edge pins the character at the boundary; it never crosses or clips past the track edge.
- (capability) CAP-4 Tunable decaying momentum: forward speed is governed by a fuel reserve (speed = fuel*k) that drains per a designer-authored AnimationCurve until it reaches zero, ending the run (MomentumEnded). Success: with no obstacles, a run decelerates to a stop purely from the curve; reshaping the curve or k in the inspector changes the feel with no code change; a harder charge (more initial fuel) goes both faster and longer.
- (capability) CAP-5 Obstacle reactions: slowing obstacles bleed fuel (feedback via SlowedDown), deadly obstacles end the run (Crashed); both detected by trigger colliders. Success: entering a slowing obstacle's trigger drops fuel (visible deceleration) without ending the run; entering a deadly obstacle's trigger raises Crashed and the run ends.
- (capability) CAP-6 Distance tracking: TraveledDistance accumulates total path length (sum of per-frame Move-delta magnitudes, lateral included) and resets on Launch. Success: TraveledDistance increases every frame the character moves, weaving adds to it, and it reads 0 immediately after a new Launch.
- (capability) CAP-7 Per-level layout via prefab: a level is a prefab holding the track mesh, left/right boundary transforms, and spawn point; swapping the prefab swaps the level. Success: a new level prefab with different geometry/boundaries/spawn runs with zero code change to the character or states.
- (capability) CAP-8 Clean respawn: the character can be reset to its spawn position/state so a new run can start from the initial pose. Success: after a reset the character stands at spawn with fuel/distance/steer-target zeroed and the CharacterController in a valid state, ready for the next Launch.
- (constraint) Movement is script-driven and kinematic via CharacterController.Move(); NO Unity physics forces, no Rigidbody, no realistic bounce/collision response — every number must be inspector-parametrizable.
- (constraint) The Character is the self-driving actor (a concrete subclass of the existing Character.cs stub); the state machine never drives physics — it only commands Launch(power, direction) and reacts to SlowedDown/Crashed/MomentumEnded. Honors spec-gameplay-state-machine.
- (constraint) Momentum model: speed = fuel * k; fuel drains each frame by curve.Evaluate(fuel/initialFuel)*dt; initialFuel is seeded by charge strength so one value scales both peak speed and run duration; slowing obstacles deduct fuel directly; MomentumEnded fires at fuel<=0.
- (constraint) The drain curve must stay > 0 across its whole range (or apply a min-drain floor), or fuel plateaus and MomentumEnded never fires — guaranteed termination is a requirement.
- (constraint) Steering = target-X lerp clamped to the level's left/right boundary transforms BEFORE the move; this one mechanism provides steering, boundary enforcement, and collision safety, with CharacterController collide-and-slide as backstop.
- (constraint) Distance = sum of per-frame CharacterController.Move delta magnitudes (lateral included), exposed as TraveledDistance, reset to 0 on Launch.
- (constraint) Obstacles are authored in the level prefab and detected via trigger colliders; a slowing obstacle deducts fuel (raises SlowedDown), a deadly obstacle raises Crashed. No physics collision response.
- (constraint) Respawn resets safely: toggle CharacterController.enabled false around writing transform.position/rotation=spawn, then re-enable; also zero fuel, distance, and steer-target. Executed by the Character on command (during the state machine's fade).
- (decision) Non-goal: real drag-based Charge (a stub ChargeState with serialized power/direction stands in for now — owned by spec-gameplay-state-machine).
- (decision) Non-goal: animations (forward a bare character prefab).
- (decision) Non-goal now: variable-width tracks (series of boundary pairs) and multiple level layouts beyond one — the prefab-per-level architecture allows them; building them is later.
- (decision) Non-goal: Unity physics simulation (no Rigidbody forces/bounce), rewards sub-flow, and cross-session persistence.
- (assumption) charge strength and aim direction arrive via the existing Character.Launch(power, direction) / ShotState.Configure(power, direction) contract.
- (assumption) k (fuel->speed) and the drain AnimationCurve are inspector fields; exact values and the chargeStrength->initialFuel mapping are tuning, not fixed here.
- (question) Exact chargeStrength->initialFuel mapping (linear, curve, clamps)? Left for tuning.
- (question) Total-path distance lets weaving inflate the score — intended risk/reward, or should lateral be capped/weighted? Parked in brainstorm, undecided.
- (question) Steering responsiveness while slowed: is the target-X lerp rate constant, or scaled by current forward speed (feel)?
