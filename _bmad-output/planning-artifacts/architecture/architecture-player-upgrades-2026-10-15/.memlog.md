- (constraint) Inherited from spec-save-system (binding): save system is STATELESS (S1) — it does not hold live state, so a consumer must own the live PlayerUpgradesData; persistence is UniTask<IResult<T>> (non-throwing); Newtonsoft serialization; VContainer DI; key-suffix versioning, no migration.
- (constraint) Inherited project conventions (CLAUDE.md): no comments, var preferred, underscore privates, UniTask not coroutines, code under Assets/MiraculousSurfers/.
- (decision) ADOPTED: the Upgrade service is the stateful owner of the live PlayerUpgradesData (it is the consumer the stateless save system defers to). Binds: exactly one in-memory owner of upgrade state; Prevents: two holders of divergent upgrade copies.
- (decision) Model A (value-step, flat): PlayerUpgradesData keeps storing a float VALUE per param (unchanged from implemented code); a purchase adds a step to the value; gameplay reads the stored float directly. Binds: save data shape stays 4 floats; Prevents: a consumer inventing a level/int representation.
- (decision) Step/cost PROVIDER is a seam: now a simple value (constant or serialized per param), FUTURE a configuration system supplies per-param steps (and likely costs/caps). The service depends on a provider abstraction it does not own, so swapping to the config later touches no callers. Binds: step/cost come from an injected provider, not hardcoded in callers.
- (decision) Single currency = coins; no CurrencyType enum (YAGNI). Price is a single long. Wallet is mocked now: non-persistent in-memory long seeded with a starting balance for testing purchases.
- (decision) Wallet contract IWalletService (injected via DI): long Coins { get; } + bool TrySpend(long amount) atomic check-and-charge (false if insufficient). Upgrades depend ONLY on this interface; the real currency system must later satisfy the same contract. Binds: upgrade->wallet coupling is this interface; Prevents: upgrades reaching into a concrete wallet or a second balance source.
- (decision) Purchase flow (triggered by future [upgrade] tap): price = provider.NextCost(param, currentValue) -> wallet.TrySpend(price) -> if charged, apply step to in-memory param value -> persist upgrades via IDataSaveSystem.SaveAsync. Affordability for UI = Coins >= price (no charge).
- (decision) D1 optimistic purchase integrity: if SaveAsync fails after charge+apply, keep the in-memory upgrade (memory is source of truth), log it, and return a result with persisted=false; a later successful save reconciles. Binds: TryUpgrade returns a result reporting whether it persisted; Prevents: a caller assuming a purchase is durably saved.
- (question) Revisit D1->D2 (refund+revert rollback) when the real currency/wallet system becomes durable (persistent coin ledger). Until then cross-system transactionality is deferred.
- (decision) IUpgradeService contract: UpgradeParam enum key {LaunchPower,Speed,SteeringResponsiveness,CollectibleValue}; raw non-failing queries GetValue(param):float, GetNextCost(param):long, CanUpgrade(param):bool; command TryUpgrade(param):IResult<UpgradePurchase>; event Action<UpgradeParam> Changed fired after a successful upgrade. Gameplay reads multipliers via GetValue (service is sole owner), NOT off PlayerUpgradesData. Binds: UI + gameplay bind to this interface and enum; Prevents: divergent param addressing or a second reader of save data.
- (decision) TryUpgrade reuses MiraculousSurfers.Core.Result (from save system): returns IResult<UpgradePurchase> where UpgradePurchase{bool Applied; bool Persisted; float NewValue}. Ok for all expected outcomes (unaffordable=>Applied=false; applied-but-save-failed=>Persisted=false per D1); Result.Fail reserved for an unexpected exception. Invariant: every fallible Upgrade op returns IResult<T> reusing Core.Result, matching the save/load idiom; pure queries return raw types.
- (decision) F2 (prototype, single scene/scope): IWalletService (mock) and IUpgradeService register in the existing GameplayLifetimeScope alongside IDataSaveSystem<PlayerUpgradesData>, as Singletons. Single-owner invariant holds because there is exactly one scope. No root scope, no change to save-system spec placement.
- (question) Revisit F2->F1: promote meta services (save, wallet, upgrades) to a root/parent LifetimeScope when a second scene (e.g. Home screen) appears, so state survives scene loads and both scenes share one instance.
- (decision) SUPERSEDES the narrow 'IUpgradeStepProvider': the step/price source is a first-class Game Configuration system, IGameConfigurationSystem, mirroring the reference project's IGameConfigurationSystem/LocalGameConfigurationSystem. It exposes authored game config including, per UpgradeParam, the upgrade steps and the price of each step. Backed NOW by a ScriptableObject read by a LocalGameConfigurationSystem (the real local impl, not a throwaway constant). Upgrade service depends on IGameConfigurationSystem for steps+prices. Binds: tuning/pricing source is IGameConfigurationSystem (SO-backed); Prevents: hardcoded steps/prices or an upgrade-only provider.
- (decision) Persisted state = integer upgrade INDEX per UpgradeParam (supersedes Model A float-value storage). PlayerUpgradesData becomes 4 ints (indices), default 0; the multiplier value is DERIVED via IGameConfigurationSystem.Value(param,index), never stored. Binds: saved state = 4 ints; value is looked up; Prevents: two sources of truth for the multiplier. Impact: revises already-shipped PlayerUpgradesData/PlayerUpgradesSaveSystem and save-system spec CAP-8 (defaults all 1.0 -> indices default 0) — reconcile on build.
- (decision) IGameConfigurationSystem index-addressed contract: int StepCount(param), float Value(param,index) [index 0 = base, e.g. 1], int Price(param,index) [cost to reach index; upgrade i->i+1 = Price(i+1)], bool HasNext(param,index). SO authors per-param arrays of {value,price} by step; max-level = HasNext false.
- (decision) Coins and prices are int (not long). IWalletService: int Coins { get; } + bool TrySpend(int amount). Supersedes earlier long usage in wallet/config contracts.
- (decision) Upgrade service loads state on scope start via VContainer IAsyncStartable.StartAsync (awaits IDataSaveSystem.LoadAsync into the in-memory index state); on load failure falls back to CreateDefault() per save-system F2a, so it always starts valid.
- (decision) AD-2 tighten (reviewer): on load, UpgradeService clamps each saved index to [0, StepCount(param)]. An out-of-range index (config ladder shrank between builds, or bad data) clamps to max and never indexes the config out of range or throws. Prevents: loader-vs-config divergence/crash.
- (decision) AD-4 tighten (reviewer): GetNextCost(param) returns 0 when HasNext is false (maxed); callers gate price display on CanUpgrade/HasNext. Changed fires whenever the in-memory index actually changes (Applied=true), independent of Persisted, so UI refreshes even when a save failed. Prevents: two UI/gameplay readers diverging on max-price display and on refresh-after-non-persisted-apply.
